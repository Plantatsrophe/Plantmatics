## 1. Non-Negotiable Code and Documentation Hygiene

* **Zero `_archive` Coupling:** Never import or source files from `scripts/_archive/`, `data/_archive/`, or `outputs/_archive/`. Active code must fail fast when required inputs are missing.
* **Zero Obsolete Framework Remnants:** The pipeline operates purely on LeafMachine3 (`lm3`) ONNX Runtime and modern Python and R statistical stacks without modifying files inside `LeafMachine3/`. Active files must contain zero obsolete segmentation framework remnants and zero retired helper tokens.
* **300-DPI PNG-Only Figure Architecture:** All 14 canonical publication plates (`fig02a` through `fig07b`) and native `LeafMachine3` visual caches (`lm3_assets/`, `ect_overlays/`, and `lm3_sheet_overlays/`) export strictly as 300-DPI `.png` rasters (`0` `.pdf` figure outputs) with unfilled hollow scatterplot symbols, combinatorial 60-taxon palette-and-shape scaling, and ICN rank-aware italicization.
* **Dynamic Genus-Wide Discovery:** The harvester queries genus-wide occurrences dynamically through `discover_genus_packera_species_gbif()`. Explicit `taxon` or `focal_taxon` runs restrict analysis strictly to the specified taxa and reconcile SQLite `vouchers` with `curated_vouchers.csv` via `reconcile_curated_vouchers_csv_with_db()`.
* **Positive Present-State Documentation:** Maintain all documentation strictly in terms of active capabilities and positive requirements alongside current implementations.
* **Zero Silent Synthetic Data:** Never generate unflagged random embeddings (`np.random.randn`) or synthetic raster values when `demo` mode is inactive. Synthetic data generation requires explicit `demo` mode (`PLANTMATICS_DEMO_MODE=1`, with `PACKERA_DEMO_MODE=1` compatibility), which isolates writes to ephemeral SQLite (`demo_ephemeral.sqlite`) and leaves canonical stores untouched.
* **Authentic Voice and Documentation Standard (`@write-in-my-voice`):** All prose and SOP descriptions alongside `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, and `docs/*.md` must follow Brandon Fuller's authentic voice (Writing DNA v5.2 in [`.agents/skills/write-in-my-voice/SKILL.md`](.agents/skills/write-in-my-voice/SKILL.md)), with zero em dashes, zero en dashes, zero tricolons, zero trailing participial clauses, and active first-person empirical framing.
* **Dual Virtualenv Boundaries:**
  * `.venv`: Primary orchestration (`main.py`, `run_pipeline.sh`), environmental layer downloads, and DuckDB/SQLite management.
  * `.venv_LM3` (`LeafMachine3/.venv`): LeafMachine3 ONNX Runtime isolation (YOLO26x, UNet++ v9, Ruler solver, ECT, and visual product rendering), relying strictly on standard-library `sqlite3`.
* **Verification Gate:** Verify code hygiene and cross-stage contracts via `.venv/bin/python scripts/tests/run_audit.py` (or `.venv/bin/python scripts/tests/run_audit.py --fast` for rapid Python-only iteration before running the full warm-R audit).

## 3. Two-Tier Storage Architecture and Relational Contracts

The central SQLite WAL database (`data/plantmatics.sqlite`, automatically migrated atomically without data loss from legacy `data/packera_pipeline.sqlite`; configurable via `PLANTMATICS_DB_PATH`, `PLANTMATICS_RUN_DIR`, `PLANTMATICS_GENOMICS_DIR`, plus `PLANTMATICS_CYTOLOGY_DIR` with `PACKERA_*` fallback compatibility) pairs with synchronized atomic CSV snapshots:
* **Tier A: Canonical Shared Store (`data/`):** Houses invariant Step 01 and Step 02 specimen records, WebP scans, binary masks, 120-vertex tip-up contours, $32 \times 360$ ECT `.npy` matrices, organ crops, canonical manifests, the environmental cache, flat `data/taxonomy/` backbone/NatureServe CSVs, flat `data/cytology/` chromosome/C-value tables, plus `genomic_samples` metadata/QC.
* **Tier B: Run-Scoped Stores (`runs/<RUN_ID>/` with `runs/latest` and `runs/latest_eastern_na`):** Isolates active cohort filtering and Step 03 to 07 statistical tables alongside written reports plus geospatial rasters and 300-DPI PNG figures. Both flat single-level `run_id` keys (`runs/<RUN_ID>/` linked by `runs/latest`) and nested hierarchical monograph `run_id` keys (`<PARENT_RUN_ID>/00_genus_wide/<Stage>` and `<PARENT_RUN_ID>/<Species_Slug>/<Stage>` inside `runs/<PARENT_RUN_ID>/`, linked by `runs/latest_eastern_na`) resolve losslessly across Python and R as well as Bash and stay strictly isolated by `run_id` inside SQLite Tier B tables.
* **Segment and Run Reset (`purge-segments` / `purge-old-data`):** Invoking `purge_segments_and_runs()` in `scripts/core/db.py` clears Step 02 to 07 masks, contours, ECT matrices, organ crops, downstream CSVs, `runs/`, and SQLite Step 02 to 07 rows (`VACUUM`), whereas Step 01 `vouchers`, `taxon_synonyms`, `taxon_backbone_profiles`, `natureserve_subnational_ranges`, `environmental_cache`, `genomic_samples`, `cytological_records`, `taxon_cytology_summary`, `data/raw_vouchers/`, `data/taxonomy/`, `data/cytology/`, `data/genomics/`, plus `data/tables/curated_vouchers.csv` remain intact (non-destructive Tier B `purge-runs-only` resets likewise preserve Step 02 imagery/contours, `genomic_samples`, Tier A taxonomic backbone tables, plus Tier A cytology tables).

### Mandatory Cross-Language Schema and Handoff Invariants

* **Composite Grouping Key `(catalogNumber, plant_individual_id)`:** All joins across Python and R must group by this composite key and never collapse multi-plant sheets to `plant_individual_id = 0`.
* **Schema Synchronization (`PLANTMATICS_SCHEMA_USER_VERSION = 20261127`):** Python (`db_schema.py`) and R (`db_utils.R`) must maintain identical table schemas and `v_integrative_triage_master` definitions (keeping `PACKERA_SCHEMA_USER_VERSION` as an alias).
* **Genus-Agnostic Config Scoping (`TaxaConfig.target_genus` / `TaxaConfig.target_family`):** Config readers and harvesters resolve active genus and family dynamically via `resolve_target_genus()` (`"Packera"` default) and `resolve_target_family()` (`"Asteraceae"` default), so non-*Packera* runs (e.g., *Solidago*) swap cleanly without source edits.
* **Read-Only LeafMachine3 Step 02 Adapter and Step 03 R EFA QC:** Step 02 persists 100% uncut native `LeafMachine3` binary masks (intersected only with LM3 `specimen_paper_cleaned_mask` interior pockets), native symmetry/QC metrics, 120-vertex tip-up `lamina_base`-anchored contours, and $32 \times 360$ ECT matrices to SQLite without mask mutation or destructive Python-side leaf dropping; Step 03 (`evaluate_step03_lm3_efa_qc`) filters unresolved clumps in R before running `coo_center() %>% coo_scale()` and `Momocs::efourier(..., norm = FALSE, start = FALSE)` (preserving reniform/obovate $L/W < 1.0$ homology without `norm = TRUE` ellipse flipping).
* **Stratified Authority Pool Cap and Type Control:** Active anchors enforce `Tier_0_Type = 3.0`, `Tier_1_Gold = 2.0`, `Tier_2_Silver = 0.75` (capped at $\le 40\%$ of active pool weight when $N_{\text{type+gold}} \ge 5$), `Promoted_Bronze = 0.50`, and unpromoted `Tier_3_Bronze = 0.0` (with `authority_weight == 0` enforced on passive and MCD-pruned sheets alongside heterotypic-demoted types plus open/hybrid and confident label-noise rows). Homotypic *sensu stricto* name-bearing types retain MCD immunity (`Tier_0_Type_Anchor`) and anchor per-species typical morphotypes ($c^*_k$), whereas extreme heterotypic types beyond $\chi^2_{0.995, p}$ demote to `Passive_Heterotypic_Type_Audit` (and flag `Heterotypic_Type_Divergence_*` at `HIGH` priority when exceeding $\chi^2_{0.99, p}$ against an empirical homotypic centroid), and all types follow Rules A, B, and C alongside the Stage 3 Population-Cohesion Lineage Gate (`cryptic_cluster_cohesion_pass`).
